# 周末城市探索指南 · 高保真产品原型

> 2027 届秋招 · AI 产品经理作品集 ｜ 作者：布莱恩

一款面向大学生的**本地周末探索工具**：用「智能决策 + 实时组队执行」解决"不知道去哪、约不到人、计划易崩"。我们不做又一个内容平台，而是帮你看少一点、走多一点。

---

## 一、如何访问（给面试官）

🌐 **在线原型（最新版）**：**[https://gl7lmt.csb.app](https://gl7lmt.csb.app)**

点击打开后，请注意以下几点：

- **加载**：原型托管在 CodeSandbox，首次打开可能需要 **3–5 秒** 加载，请稍候。
- **定位授权**：浏览器会请求地理位置权限。**允许**可体验"就近推荐"；**拒绝**会自动回退到默认城市（深圳），功能完全可用，不影响体验。
- **演示数据**：所有景点、餐厅、天气均为**演示用采样数据**（页面已标注"示范版"），并非真实商业数据；接真实 API 只需替换一个数据文件。
- **本地保存**：「我的周末」里的打卡、组队数据保存在**浏览器本地（localStorage）**，换浏览器或清空缓存会重置——这是原型演示层的设计，不是 bug。
- **设备**：推荐使用 Chrome / Safari 的**手机或桌面浏览器**打开，已做移动端响应式适配。
- **城市状态**：深圳 / 上海 / 北京 / 成都 **已开通**；广州 / 杭州 / 武汉 / 西安 / 重庆 为"筹备中"（可体验申请开通流程）。

## 二、这个产品做了什么（30 秒看懂）

| 维度 | 说明 |
|------|------|
| **一句话定位** | 帮大学生用 30 秒定下周末去哪，并一键约到同行的人 |
| **目标人群** | 18–24 岁在校大学生：价格敏感、搭子文化原生、对 AI 接受度高 |
| **两大真痛点** | ② 决策疲劳（选项越多越不会选）｜ ③ 执行层（约不到人、计划易崩） |
| **我们的解法** | 四维智能排序 + 匹配度人话理由 + 一句话对话决策 + 完整一天行程 + 即时组队 |
| **产品边界** | 不做 OTA/支付、不做 UGC 社区运营、不自建导航、不做长途出境 |
| **当前阶段** | 高保真交互原型（前端演示层），用于验证产品思路与交互 |

完整产品定位 👉 [`产品定位梳理.md`](./产品定位梳理.md)

## 三、主要功能与使用方式

### 1️⃣ 一句话对话式决策（探索推荐 · 对应痛点②）
- **怎么用**：顶部输入框直接用自然语言说一句，例如「两个人 人均一百 想看展 下午去」——**兴趣 / 预算 / 同行 / 场地全部可选**，不填也能用。
- **做了什么**：自动解析意图，并用一句人话**复述"我理解成…"**（不对用户做黑箱）；按 偏好 × 天气 × 预算 × 人数 四维实时排序，每个结果给出 **匹配度分数 + 一句推荐理由**。
- **决策卸载**：懒得选时点「帮我挑 3 个」，直接给 3 个最匹配的结果。

### 2️⃣ 一键排成「完整的一天」（痛点②→③ 的铰链）
- **怎么用**：匹配到想去的活动后，点「直接排成一整天」，一键落成 **分天 + 分时段** 的行程。
- **做了什么**：自动分 上午 / 下午 / 傍晚 / 夜间 四时段排布、就近插入**吃饭**站点、计算站间**通勤分钟与公里数**、雨天自动把室内项前移并标注"备伞"。
- **预算可信**：单餐费用上限 = 预算的 40%；超预算时 KPI 标红并给「按预算精简」按钮（至少保留 3 个去处）。

### 3️⃣ 组队出发（对应痛点③）
- **怎么用**：在活动或"没人组队的去处"上一键发起 / 加入队伍，支持满员、退出状态。
- **做了什么**：把"推荐活动 → 为该活动即时组队 → 一起执行"串成闭环；集合点可一键唤起高德地图导航（调地图，不自建）。

### 4️⃣ 我的周末（轻量沉淀 · 对应④留存钩子）
- **怎么用**：把想去 / 去过的活动加入行程单、打卡记录、发布轻量攻略。
- **定位**：刻意**轻量做**，不与核心痛点 ②③ 抢视觉权重——这是产品边界的主动取舍。

## 四、产品设计的几个关键决策（面向面试）

- **重 ②③、轻 ④**：决策疲劳与执行层是真实痛点，也是商业模式所在；打卡 / 攻略只是留存钩子，过度设计会暴露"定位自相矛盾"。
- **不做内容社区**：小红书 / 抖音已把"内容"做满，我们把差异放在"更少的决策摩擦"——不抢内容平台饭碗，不做 UGC 流量运营。
- **不做 OTA / 支付 / 自建导航**：守住边界，不碰资金、不重复造轮子，地图用 deep-link 唤起。
- **信息分散怎么处理**：不把它当"要新做的功能"，而是实现 ②③ 的数据底座——前期用每城人工精选数据跑通，再走合作 / 官方开放数据。

## 五、技术说明（轻量）

- **纯前端、零框架**：原生 HTML / CSS / JS，无需安装，打开即用。
- **本地持久化**：偏好、行程、打卡存于 `localStorage`，刷新不丢。
- **单文件分发**：构建产物为单个 `index.html`（CSS / JS 全内联，约 149KB），便于托管与演示。
- **数据驱动**：城市、活动、天气均为数据驱动，新增城市 = 加一条数据。
